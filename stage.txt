🔴 КРИТИЧЕСКАЯ ПРОБЛЕМА
───────────────────────────────────────────────────────────────
НАЗВАНИЕ: Go Module Resolution для локальных Protobuf пакетов

ОПИСАНИЕ:
Go компилятор не может найти локально сгенерированные protobuf 
пакеты (internal/gen/*) и пытается скачать их с GitHub как 
внешние модули, что приводит к ошибке:

  "cannot find module providing package 
   github.com/voice-diary/backend/internal/gen/auth: 
   git ls-remote -q origin... exit status 128"

ТЕХНИЧЕСКИЕ ДЕТАЛИ:
- Protobuf файлы сгенерированы локально в backend/internal/gen/
- Файлы копируются в Docker образ через COPY internal ./internal
- go.mod содержит: replace github.com/voice-diary/backend => ./
- Используется флаг -mod=mod при компиляции
- Установлена переменная GOPRIVATE=github.com/voice-diary/backend
- Но Go ВСЕ РАВНО пытается найти internal/gen как внешний модуль

ПОЧЕМУ ЭТО ПРОИСХОДИТ:
1. Replace directive работает только для корневого модуля
2. Go воспринимает internal/gen/* как sub-пакеты, которые нужно 
   найти как отдельные модули
3. -mod=mod не решает проблему поиска внешних модулей
4. GOPRIVATE работает только если модуль уже есть в go.sum

КАКИЕ СЕРВИСЫ ЗАТРОНУТЫ:
- API-Gateway: импортирует ВСЕ protobuf пакеты (auth, diary, 
  storage, search, notification)
- Diary-service: импортирует diary protobuf
- Storage-service: импортирует storage protobuf
- Search-service: импортирует search protobuf

ПОЧЕМУ AUTH-SERVICE СОБРАЛСЯ:
Auth-service собрался из КЭШИРОВАННЫХ слоёв Docker, где был 
правильный go.sum. При пересборке с --no-cache он тоже падает 
с той же ошибкой.
